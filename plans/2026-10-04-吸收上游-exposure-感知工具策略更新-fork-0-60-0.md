# 吸收上游 exposure 感知工具策略更新（fork 0.60.0）

## 摘要

把上游 `dbc6e8ee`（原生 MCP 工具 opt-in）+ `9621cda4`（工具可用性澄清）+ `403fb72b`（指引 session-safe）三个提交吸收进本 fork，适配 srt 沙箱架构：让 Plan 模式理解 Pi 1.0 的 `ToolExposure` 与原生 MCP/内置扩展工具；收紧 `isBuiltinTool` 使注解路径覆盖它们；嵌套调用按 `parentToolCallId` 路由校验；统一菜单呈现并用 `sanitizeTerminalText` 消毒不可信文本；为未激活的 grep/find/ls 提供可操作指引。不吸收 `acb3aaf3`（命令 allowlist 已被 srt 沙箱取代）与版本号类提交。

## 探查结论（根因与事实）

- Pi 1.0.1 自带 4 个内置扩展（codemode/llama/mcp/tool-search），其工具 sourceInfo 为 `{source:"builtin", path:"builtin:mcp"}` 等。fork 的 `isBuiltinTool` 只看 `source==="builtin"` → 这些工具落入"未知内置名 → blocked"，`readOnlyHint` 自动放行（0.59.1）对它们完全失效。**原生 MCP 工具（默认 exposure 为 `codemode`）当前在 Plan 模式一律被拦。**
- `ToolCallEvent` 带 `parentToolCallId`（codemode 脚本等工具发起的嵌套调用标识）；fork 不区分路由，把"不在 active 集合"一律拦截，嵌套调用语义错误。
- MCP 工具名/描述是服务器提供的不可信文本；fork 的启动/设置菜单未消毒（本地 `safeTerminalText` 只处理 C0/C1，不处理 bidi/OSC 序列如 `\u202e`、`]52;c;`）。
- `annotations` 仅 MCP 工具（`toToolAnnotations`）与扩展自愿申报存在；Pi 8 个核心内置工具（read/bash/edit/write/grep/find/ls/powershell）无注解 → 名单分类仍必要，`tool-policy.ts` 保留但收紧到核心 8 件套。
- fork 的 `modeContractFromMessage` 已有 `details.mode` + marker 前缀兜底 → 合约措辞变更不破坏旧会话 resume，无需上游的 SHA pin。
- `@narumitw/pi-tui-kit@0.59.0` 已导出 `sanitizeTerminalText` 与 `./testing` 子路径；`ToolExposure` 类型 Pi 1.0.1 已导出。
- fork 从 `./src/index.ts` 由 Jiti 直接加载（无 dist 构建）→ 新增源文件无需构建接线。
- 独立可运行测试：finalization-request、fresh-handoff-coordinator、helper-tool-visibility、mode-contract、plan-docs、presentation、settings 等 8 个文件（58 测试，当前全绿）；其余 24 个文件依赖 monorepo harness（`../../../test/support.js`），已知限制。
- `mode-contract.test.ts` 不断言工具策略句 → 合约措辞变更不破独立测试。

## 行为变更（按行为分组）

### 1. 工具分类收紧 — `src/tool-policy.ts`
- `isBuiltinTool`：仅 `source==="builtin"` 且（无 path 或 `path === builtin:<name>` 且非 model-only）才算核心内置（上游语义）；内置扩展、普通扩展、MCP 工具全部走注解路径：`readOnlyHint===true && destructiveHint!==true` → `read-only`（自动放行），否则 `user-opt-in`。
- 缺 `sourceInfo.source` → `blocked`（fail-closed，拦截理由 "safe policy metadata is unavailable"）。
- 核心名单（read/grep/find/ls 只读、bash 沙箱、edit/write/powershell blocked）不变；`toolPolicyLabel` 对缺 source 的 blocked 显示 "policy metadata unavailable"。

### 2. exposure 感知可用性 — 新增 `src/tool-availability.ts`（照搬上游 27 行）
- `planModeToolAvailability(tool, activeNames, route)`：hidden→`hidden`；model-only：nested→`model-only`（拦截"不能被其他工具调用"），model/selection→active?`available`:`inactive`；codemode/deferred：model→active?`available`:`inactive`，nested/selection→`available`；undefined/direct（旧 Pi）→active?`available`:`inactive`；未知→`unsupported`。

### 3. tool_call 拦截路由 — `src/plan-mode.ts`
- 在 classify blocked 之后、allowed 检查之前插入可用性检查：`route = event.parentToolCallId ? "nested" : "model"`，替换现有 `!activeToolNames.has(...)` 单一判断（现 768 行处）；block 理由区分 inactive（"was admitted...currently inactive"/"registered but inactive"）、hidden、model-only、unsupported。
- 保持不变：edit/write 的 plans 目录例外与拦截、powershell 拦截、plan helper 直通、bash 的 srt 包裹（嵌套 bash 调用同样包裹）、`admitLateActivatedPlanTool` 晚激活放行（其前置条件由"active"改按可用性语义）。
- `activePlanPolicyTools` → `availablePlanPolicyTools`（selection 路由可用性过滤），`desiredPlanModeToolNames`/`automaticPlanModeToolNames`/`resolvePlanModePolicyToolNames`/freeze 全部跟随；`startWithTools`（2051 行）改用 `filterAvailableSelectedToolNames(names, tools, activeToolNames)`（codemode 工具未激活也可被选中保留）。

### 4. 菜单呈现统一 + 文本消毒 — `src/tool-selection.ts`、`src/plan-launch-menu.ts`、`src/settings-menu.ts`、`src/plan-mode.ts` 菜单段
- 新增 `planModeToolSelection(tool, activeNames, retained)`：统一 label（`X — inactive in Pi` / `X — blocked by Plan policy`）、description（policy · "callable via other tools"/"model calls only" 标注 · 工具描述）、disabled/disabledReason；启动菜单（plan-mode.ts 2008 起内联构建）与设置菜单 `defaultToolItems`（643 行）全部改用它；`toolSummary`（1993 行）的可用判断改 exposure 版。
- 用 kit 的 `sanitizeTerminalText` 消毒两处菜单的 label/description/searchText/disabledReason 及 lines（plan-launch-menu 渲染处 `.map(sanitizeTerminalText)`；settings-menu 构建处）；`terminalToolName` 改用 kit 版（含 trim 与 "(unnamed tool)" 兜底）。
- grep/find/ls 未激活时 disabledReason 附指引（403fb72b 最终措辞）："on Pi with defaultTools support, use a full list including \"X\" in this session's Pi settings (preserve existing/default tools), then restart Pi"——不引用 agentDir 路径、不含 `settings.json`/`+grep` 修饰符示例。
- 设置菜单 toggle-tool 守卫（494 行）改 `planModeToolAvailability(...) !== "available"`；"Plan policy tools" 描述 "Choose active tools" → "Choose available tools"；settings 首页工具说明行同步上游措辞。

### 5. 合约措辞 — `src/prompt.ts`
- 工具策略句更新为 fork 适配版（保留自动放行语义 + 新增路由语义）：在现有 "Harmless tools (readers, sandboxed bash, read-only-hinted extensions) are admitted automatically; tools that can mutate or reach unknown systems require the user's explicit selection." 基础上，将 "extensions" 扩为 "extension/MCP tools"，并追加："Direct and model-only tools must be active to be called; registered codemode or deferred tools may be selected without activation and then run through other tools. Every nested call is checked on its own; selecting a tool does not authorize the tools it calls."
- 兼容：旧措辞合约经 `details.mode`/marker 前缀兜底仍识别为 plan；升级后首个 Plan 请求缓存前缀失效一次（上游同样接受）。

### 6. 文档与版本
- README：Tools 段（131 行附近）补"原生 MCP/内置扩展工具按注解自动放行或显式 opt-in；codemode/deferred 工具经嵌套调用运行"；Features 相应条目。
- `docs/settings.md`：新增 "Enable inactive built-in search tools in Pi" 小节（完整列表 `{defaultTools:["read","bash","edit","write","grep","find","ls"]}` 与 Pi 0.99+ 修饰符 `{defaultTools:["+grep","+find","+ls"]}` 两个 JSON 示例、"Pi 0.99 or newer only / Do not use modifiers on older releases" 说明）；"Default Plan policy tools" 段补 MCP opt-in 说明。
- `docs/command-workflows.md` 工具选择段补一句 exposure 说明。
- CHANGELOG 新条目 + package.json → **0.60.0**（行为变化：内置扩展/MCP 工具从 blocked 变为可选，属 minor）。
